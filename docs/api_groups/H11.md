# H11 Group

This is the group of APIs between
the [Core's Partner Management Service](../services/core/S07_Partner_Management_Service.md)
and [Partner's General Information Service](../services/partner/S09_Partner_General_Information_Service.md).

This API consists of 1 API.

## H11

This API is based on RabbitMQ.

The API has 3 methods.

### H11 Method: `get_partner_info`

**Purpose**: Retrieve detailed information about a specific partner

Request body format:

```json
{
  "method": "get_partner_info",
  "params": {
    "partner_id": "uuid-string"
  },
  "id": "1234"
}
```

Response body format:

```json
{
    "id": "the corresponding request id",
    "result": {
        "status": "success or error",
        "content": "the return value of the called method"
    }
}
```

On success, the content would be the partner's detailed information:

```json
{
  "partner_id": "uuid-string",
  "partner_name": "Viettel",
  "partner_url": "https://partner.viettel.com.vn/api",
  "status": "active",
  "capabilities": ["voice", "sms", "data"],
  "max_concurrent_sessions": 100,
  "current_active_sessions": 15,
  "last_health_check": "2025-12-08T10:30:00Z",
  "health_status": "healthy"
}
```

On failure (`status == 'error'`), the content would
reflect what is going on. If the failure is
caused by some `Exception`, the content should
be `str(e)` with `e` being the `Exception` instance
that was the culprit.

In special error cases, the content must be:
- `"Partner not found"` if the partner_id does not exist in the system
- `"Partner service unavailable"` if the partner's service cannot be reached

### H11 Method: `verify_partner_connection`

**Purpose**: Verify that a partner connection is active and responding

Request body format:

```json
{
  "method": "verify_partner_connection",
  "params": {
    "partner_id": "uuid-string"
  },
  "id": "1235"
}
```

Response body format:

```json
{
    "id": "the corresponding request id",
    "result": {
        "status": "success or error",
        "content": "the return value of the called method"
    }
}
```

On success, the content would be:

```json
{
  "partner_id": "uuid-string",
  "connection_status": "active",
  "response_time_ms": 45,
  "last_successful_ping": "2025-12-08T10:30:00Z",
  "api_version": "1.0.0"
}
```

On failure (`status == 'error'`), the content would
reflect what is going on. If the failure is
caused by some `Exception`, the content should
be `str(e)` with `e` being the `Exception` instance
that was the culprit.

In special error cases, the content must be:
- `"Partner not found"` if the partner_id does not exist
- `"Connection timeout"` if the partner service does not respond within the timeout period
- `"Authentication failed"` if the API key is invalid or expired

### H11 Method: `get_partner_capabilities`

**Purpose**: Retrieve the list of services and features supported by a partner

Request body format:

```json
{
  "method": "get_partner_capabilities",
  "params": {
    "partner_id": "uuid-string"
  },
  "id": "1236"
}
```

Response body format:

```json
{
    "id": "the corresponding request id",
    "result": {
        "status": "success or error",
        "content": "the return value of the called method"
    }
}
```

On success, the content would be:

```json
{
  "partner_id": "uuid-string",
  "partner_name": "Viettel",
  "capabilities": {
    "services": ["voice", "sms", "data", "roaming"],
    "features": ["prepaid", "postpaid", "package_management", "balance_check"],
    "supported_payment_methods": ["credit_card", "bank_transfer", "e_wallet"],
    "regions": ["north", "central", "south"],
    "languages": ["vi", "en"]
  },
  "last_updated": "2025-12-08T10:00:00Z"
}
```

On failure (`status == 'error'`), the content would
reflect what is going on. If the failure is
caused by some `Exception`, the content should
be `str(e)` with `e` being the `Exception` instance
that was the culprit.

In special error cases, the content must be:
- `"Partner not found"` if the partner_id does not exist
- `"Capabilities data not available"` if the partner has not provided capability information
