# H22 Group

This is the group of HTTP APIs between
the **Core Portal**
and [Core's Knowledge Validator Service](../services/core/S05_Knowledge_Validator_Service.md).

This API consists of 1 API.

## H22

This API is based on HTTP (RESTful).

The API has 4 endpoints serving partner knowledge update management:
1.  View list of updates from partners
2.  View update details
3. Approve update
4.  Reject update

### H22 Endpoint: `GET /api/v1/partner-updates`

This endpoint is called by Core Portal to retrieve the list of knowledge updates submitted by Telcenter Partners.

Request headers:
```
Authorization: Bearer <jwt_token>
```

Query parameters:
- `status` (optional): Filter by status - `pending`, `approved`, `rejected`, `all` (default: `pending`)
- `partner_id` (optional): Filter by partner ID
- `source` (optional): Filter by source (e.g., `Viettel`, `Vinaphone`)
- `from_date` (optional): Filter updates from date (ISO 8601 format)
- `to_date` (optional): Filter updates to date (ISO 8601 format)
- `page` (optional): Page number (default: 1)
- `limit` (optional): Items per page (default: 20, max: 100)
- `sort_by` (optional): Sort field - `submitted_at`, `priority`, `entry_count` (default: `submitted_at`)
- `sort_order` (optional): `asc` or `desc` (default: `desc`)

### H22 Endpoint: `POST /api/v1/partner-updates/{update_id}/approve`

This endpoint is called by Core Portal to approve a knowledge update from a partner after validation.

Request headers:
```
Authorization: Bearer <jwt_token>
Content-Type: application/json
```

URL Parameters:
- `update_id`: The ID of the update to approve (e.g., `partner_sub_1234`)

Request body format:

```json
{
  "approval_notes": "Đã kiểm tra và xác nhận dữ liệu chính xác",
  "approved_entries": "all",
  "notify_partner": true
}
```

Approval options:
- `approved_entries`: `"all"` or array of specific entry indices to approve
- `notify_partner`: Send notification to partner (default: true)

Response format (HTTP 200 OK):

```json
{
  "status": "success",
  "update_id": "partner_sub_1234",
  "validation_id": "core_val_9012",
  "message": "Đã phê duyệt bản cập nhật thành công",
  "approval_result": {
    "approved_at": "2025-12-08T11:00:00Z",
    "approved_by": "core_employee_123",
    "total_entries": 48,
    "approved_entries": 48,
    "rejected_entries": 0,
    "stored_in_core": true,
    "synced_to_partner": true

  "next_actions": [
    "Dữ liệu đã được lưu vào Core Knowledge Database",
    "Đã đồng bộ về Partner Local Knowledge Database",
    "Thông báo đã gửi đến partner"
```

```json
}
```

### H22 Endpoint: `POST /api/v1/partner-updates/{update_id}/reject`

This endpoint is called by Core Portal to reject a knowledge update from a partner after validation.

Request headers:
```
Authorization: Bearer <jwt_token>
Content-Type: application/json
```

URL Parameters:
- `update_id`: The ID of the update to reject (e.g., `partner_sub_1234`)

Request body format:

```json
{
  "rejection_reason": "Dữ liệu không chính xác và có nhiều mâu thuẫn",
  "rejection_details": [
    {
      "entry_index": 0,
      "service_code": "SD70",
      "reason": "Mã dịch vụ trùng lặp với giá cước xung đột",
      "suggestion": "Vui lòng kiểm tra lại giá cước của gói SD70"
    },
    {
      "entry_index": 5,
      "service_code": "V120",
      "reason": "Thiếu trường bắt buộc 'Chu kỳ (ngày)'",
      "suggestion": "Bổ sung thông tin chu kỳ thanh toán"
    }
  ],
  "notify_partner": true,
  "allow_resubmit": true
}
```

Rejection options:
- `rejection_reason`: Main reason for rejection (required)
- `rejection_details`: Detailed feedback for each problematic entry (optional)
- `notify_partner`: Send notification to partner (default: true)
- `allow_resubmit`: Allow partner to fix and resubmit (default: true)

Response format (HTTP 200 OK):

```json
{
  "status": "success",
  "update_id": "partner_sub_1234",
  "validation_id": "core_val_9013",
  "message": "Đã từ chối bản cập nhật",
  "rejection_result": {
    "rejected_at": "2025-12-08T11:00:00Z",
    "rejected_by": "core_employee_123",
    "total_entries": 48,
    "rejected_entries": 48,
    "rejection_reason": "Dữ liệu không chính xác và có nhiều mâu thuẫn",
    "notification_sent": true,
    "can_resubmit": true

  "next_actions": [
    "Partner có thể xem chi tiết lý do từ chối",
```

## Configuration

Base URL should be configurable via `.env`:
- `KNOWLEDGE_VALIDATOR_SERVICE_URL` (e.g., `http://localhost:5005`)

## Notes

- All requests require JWT authentication with Core employee credentials
- Only users with validator role can approve or reject updates
- Rate limiting: 100 requests per minute per user
- Updates remain in pending status for 24 hours before auto-escalation
- Approved updates are automatically stored in Core Knowledge DB and synced back to partner
- Rejected updates can be resubmitted by partner after fixing issues
- All approval/rejection actions are logged for audit purposes
- Partners receive real-time notifications about approval/rejection status
- CORS enabled for Core Portal domain
- Validation history is retained for compliance and auditing
- Maximum entries per update: 1000
- Bulk operations supported for approving/rejecting multiple updates
