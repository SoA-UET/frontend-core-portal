# A17 Group

This is the group of APIs between
the [Core's Metrics Service](../services/core/S08_Core_Metrics_Service.md)
and [Partner's Metrics Service](../services/partner/S14_Partner_Metrics_Service.md).


## A17b - Methods API

This API is based on RabbitMQ using queues:
- Request queue: `s14_s08_requests_queue`
- Response queue: `s14_s08_responses_queue`

S14 sends method requests to S08 to query partner-specific metrics data.

The API has 2 methods.

### A17b Method: `get_partner_conversation_statistics`

S14 calls this method to retrieve comprehensive conversation statistics for a specific partner from S08.

Request body format:

```json
{
  "method": "get_partner_conversation_statistics",
  "params": {
    "partner_id": "abcdef"
  },
  "id": "001"
}
```

Response body format:

```json
{
  "id": "001",
  "result": {
    "status": "success",
    "content": {
      "partner_id": "abcdef",
      "total_conversations": 1850,
      "forwarding_conversations": 28,
      "texting_conversations": 1240,
      "calling_conversations": 582,
      "ai_failed_conversations": 245,
      "offloaded_conversations": 1605,
    }
  }
}
```

**Field descriptions:**
- `partner_id`: ID of the partner
- `total_conversations`: Total number of conversations for this partner (matching partner_id)
- `forwarding_conversations`: Number of conversations currently in FORWARDING status (matching partner_id)
- `texting_conversations`: Number of text-based conversations for this partner (matching partner_id)
- `calling_conversations`: Number of calling/audio conversations for this partner (matching partner_id)
- `ai_failed_conversations`:  Number of conversations where AI failed for this partner (matching partner_id)
- `offloaded_conversations`:  Number of conversations offloaded to this partner (matching partner_id)



On success, the content would be an object containing the conversation statistics as shown above.

On failure (`status == 'error'`), the content would
reflect what is going on. If the failure is
caused by some `Exception`, the content should
be `str(e)` with `e` being the `Exception` instance
that was the culprit.

In special error cases, the content must be:
- `"PARTNER_NOT_FOUND"` if the partner_id does not exist
- `"DB_CONNECTION_ERROR"` if S08 cannot query the database

### A17b Method: `get_partner_satisfaction_distribution`

S14 calls this method to retrieve customer satisfaction distribution for a specific partner from S08.

Request body format:

```json
{
  "method": "get_partner_satisfaction_distribution",
  "params": {
    "partner_id": "abcdef"
  },
  "id": "002"
}
```

Response body format:

```json
{
  "id": "002",
  "result": {
    "status": "success",
    "content": {
      "partner_id": "abcdef",
      "satisfaction_1": 48,
      "satisfaction_2": 92,
      "satisfaction_3": 385,
      "satisfaction_4": 1120,
      "satisfaction_5": 805,
    }
  }
}
```

**Field descriptions:**
- `partner_id`: ID of the partner
- `satisfaction_1`: Count of conversations with 1-star rating for this partner
- `satisfaction_2`: Count of conversations with 2-star rating for this partner
- `satisfaction_3`: Count of conversations with 3-star rating for this partner
- `satisfaction_4`: Count of conversations with 4-star rating for this partner
- `satisfaction_5`: Count of conversations with 5-star rating for this partner


On success, the content would be an object containing the satisfaction distribution as shown above.

On failure (`status == 'error'`), the content would
reflect what is going on. If the failure is
caused by some `Exception`, the content should
be `str(e)` with `e` being the `Exception` instance
that was the culprit.

In special error cases, the content must be:
- `"PARTNER_NOT_FOUND"` if the partner_id does not exist
- `"NO_DATA_FOUND"` if no satisfaction ratings exist for this partner
- `"DB_CONNECTION_ERROR"` if S08 cannot query the database
