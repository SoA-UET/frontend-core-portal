# A34 Group

This is the group of APIs between
the [Partner's Knowledge Update Service](../services/partner/S12_Partner_Knowledge_Update_Service.md)
and [Core's Knowledge Validator Service](../services/core/S05_Knowledge_Validator_Service.md).

**Type:** Event (fire-and-forget, no response needed)

This is a cross-system API that communicates over the Internet between Telcenter Partner and Telcenter Core systems.

This API consists of 1 API.

## A34

**Direction:** S12 (Partner) → S05 (Core)

This API is based on RabbitMQ.

The API has 3 events.

### A34 Event: `snapshot_start`

This event is emitted by S12 (Partner) to notify S05 (Core) that a snapshot transmission process is starting.

Event body format:

```json
{
  "event": "snapshot_start",
  "data": {
    "partner_id": "viettel_partner_001",
    "snapshot_id": "123456"
  }
}
```

### A34 Event: `snapshot_chunk`

This event is emitted by S12 (Partner) to transmit a chunk of the snapshot data to S05 (Core).

The chunk must be base64-encoded to ensure safe transmission over RabbitMQ.

Event body format:

```json
{
  "event": "snapshot_chunk",
  "data": {
    "partner_id": "viettel_partner_001",
    "snapshot_id": "123456",
    "seq": 1, // sequence number of this chunk
    "chunk_data_base64": "eyJrbm93bGVkZ2UiOiBbXX0="  // Base64-encoded chunk data
  }
}
```

The `chunk_data_base64` field contains a base64-encoded string
of the JSON chunk data. The raw data (before being
base64-encoded) must not exceed 256 bytes in size.

### A34 Event: `snapshot_stop`

This event is emitted by S12 (Partner) to notify S05 (Core) that the snapshot transmission process is complete.

Event body format:

```json
{
  "event": "snapshot_stop",
  "data": {
    "partner_id": "viettel_partner_001",
    "snapshot_id": "123456",
    "total_chunks": 10  // total number of chunks sent
  }
}
```

## Queue Configuration

- Event Queue: `update_validation_events`

Configurable via `.env`:
- `UPDATE_VALIDATION_EVENT_QUEUE`
