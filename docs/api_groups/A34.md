# A34 Group

This is the group of APIs between
the [Partner's Knowledge Update Service](../services/partner/S12_Partner_Knowledge_Update_Service.md)
and [Core's Knowledge Validator Service](../services/core/S05_Knowledge_Validator_Service.md).

This API consists of 1 API.

## A34

This API is based on RabbitMQ.

This is a cross-system API that communicates over the Internet between Telcenter Partner and Telcenter Core systems.

The API has 1 method.

### A34 Method: `validate_knowledge`

On failure (`status == 'error'`), the content would
reflect what is going on. If the failure is
caused by some `Exception`, the content should
be `str(e)` with `e` being the `Exception` instance
that was the culprit.

In special error cases:
- If `partner_id` is missing or unauthorized, the content must be `"Invalid or unauthorized partner_id"`
- If `source` is missing or invalid, the content must be `"Invalid or missing source field"`
- If `df` is empty or malformed, the content must be `"Invalid dataframe format"`
- If `submission_id` is missing, the content must be `"Missing submission_id"`
- If partner is not authorized to submit knowledge for this source, the content must be `"Partner not authorized for source: <source>"`
- If validation service is unavailable, the content must be `"Core validation service temporarily unavailable"`
- If all entries are rejected, the content must be `"All entries rejected during validation"`

## Queue Configuration

- Request Queue: `core_knowledge_validation_requests`
- Response Queue: `core_knowledge_validation_responses`

Both queues should be configurable via `.env` file with the following variables:
- `CORE_KNOWLEDGE_VALIDATION_REQUEST_QUEUE`
- `CORE_KNOWLEDGE_VALIDATION_RESPONSE_QUEUE`

## Notes

- This is a cross-system API communicating over the Internet, so implement retry logic and timeouts
- Validation typically takes 2-10 seconds depending on the number of entries
- The `_validation_score` field indicates the confidence level of the validation (0.0 to 1.0)
- Validated data may be slightly modified (normalized, enriched) compared to submitted data
- Partner should handle `partial_approval` status and decide how to process rejected entries
- All validation requests are logged for compliance and auditing
- Security: Implement authentication tokens in metadata for partner verification
