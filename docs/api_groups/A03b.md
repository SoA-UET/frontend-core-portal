# A03 Group

This is the group of APIs between
the [Core's Consultation Service](../services/core/S01_Consultation_Service.md)
and [Core's Metrics Service](../services/core/S08_Metrics_Service.md).


## A03b - Methods API

This API is based on RabbitMQ using queues:
- Request queue: `s08_s01_requests_queue`
- Response queue: `s08_s01_responses_queue`

In this API, S08 sends method requests to get aggregated metrics data from S01.

The API has 3 methods.

### A03b Method: `get_conversation_statistics`

Request body format:

```json
{
  "method": "get_conversation_statistics",
  "params": {},
  "id": "001"
}
```

Response body format:

```json
{
    "id": "001",
    "result": {
        "status": "success",
        "content": {
          "total_conversations": 1000,
          "ai_failed_conversations": 150,
          "forwarding_conversations": 100,
          "texting_conversations": 600,
          "calling_conversations": 300,
          "offloaded_conversations": 850
        }
    }
}
```

**Field descriptions:**
- `total_conversations`: Total number of all conversations
- `ai_failed_conversations`: Conversations where status is one of statuses such as: FORWARDING, HUMAN_AGENT_TEXTING, HUMAN_AGENT_CALLING
- `forwarding_conversations`: Conversations with status = FORWARDING
- `texting_conversations`: Total number of conversations with status HUMAN_AGENT_TEXTING and AI_AGENT_TEXTING.
- `calling_conversations`: Total number of conversations with status HUMAN_AGENT_CALLING or AI_AGENT_CALLING.
- `offloaded_conversations`: total_conversations - ai_failed_conversations

On success, the content would be an object containing the conversation statistics as shown above.

On failure (`status == 'error'`), the content would
reflect what is going on. If the failure is
caused by some `Exception`, the content should
be `str(e)` with `e` being the `Exception` instance
that was the culprit.

In special error cases, the content must be "DB_CONNECTION_ERROR" if S01 cannot query the Conversation DB to fetch stats.

### A03b Method: `get_customer_satisfaction_distribution`

Request body format:

```json
{
  "method": "get_customer_satisfaction_distribution",
  "params": {},
  "id": "002"
}
```

Response body format:

```json
{
    "id": "002",
    "result": {
        "status": "success",
        "content": {
          "satisfaction_1": 10,
          "satisfaction_2": 25,
          "satisfaction_3": 150,
          "satisfaction_4": 400,
          "satisfaction_5": 415
        }
    }
}
```

**Field descriptions:**
- `satisfaction_1` through `satisfaction_5`: Count of conversations with each satisfaction rating (1-5)

On success, the content would be an object containing the satisfaction distribution as shown above.

On failure (`status == 'error'`), the content would
reflect what is going on. If the failure is
caused by some `Exception`, the content should
be `str(e)` with `e` being the `Exception` instance
that was the culprit.

In special error cases, the content must be "NO_DATA_FOUND" if no satisfaction ratings exist.

### A03b Method: `get_offloaded_conversations_by_partner`

Request body format:

```json
{
  "method": "get_offloaded_conversations_by_partner",
  "params": {},
  "id": "003"
}
```

Response body format:

```json
{
    "id": "003",
    "result": {
        "status": "success",
        "content": {
          "abcdef": 10,
          "xyzdef": 12,
          "ghijkl": 5
        }
    }
}
```

**Content format:** A dictionary where keys are partner_ids and values are the count of conversations offloaded to that partner.

On success, the content would be an object containing partner-specific offloading counts as shown above.

On failure (`status == 'error'`), the content would
reflect what is going on. If the failure is
caused by some `Exception`, the content should
be `str(e)` with `e` being the `Exception` instance
that was the culprit.

In special error cases, the content must be "NO_DATA_FOUND" if no offloading data exists.
