# A09 Group

This is the group of APIs between
the [Partner's Authorized Partner Gateway Service](../services/partner/S16_Authorized_Partner_Gateway_Service.md)
and [Core's Partner Management Service](../services/core/S07_Partner_Management_Service.md).

This API consists of 1 API.

## A09

This API is based on RabbitMQ.

The API has 3 methods.

### A09 Method: `get_partner_endpoint`

**Purpose**: Query the endpoint URL of a specific partner by name or ID

Request body format:

```json
{
  "method": "get_partner_endpoint",
  "params": {
    "partner_identifier": "viettel"
  },
  "id": "1234"
}
```

The `partner_identifier` can be either the partner's name (e.g., "viettel", "mobifone") or the partner's UUID.

Response body format:

```json
{
    "id": "the corresponding request id",
    "result": {
        "status": "success or error",
        "content": "the return value of the called method"
    }
}
```

On success, the content would be:

```json
{
  "partner_id": "uuid-string",
  "partner_name": "Viettel",
  "endpoint_url": "https://partner.viettel.com.vn/api",
  "api_version": "1.0.0",
  "status": "active",
  "last_health_check": "2025-12-08T10:30:00Z"
}
```

On failure (`status == 'error'`), the content would
reflect what is going on. If the failure is
caused by some `Exception`, the content should
be `str(e)` with `e` being the `Exception` instance
that was the culprit.

In special error cases, the content must be:
- `"Partner not found"` if the partner_identifier does not match any partner in the system
- `"Partner inactive"` if the partner exists but is not currently active

### A09 Method: `get_core_endpoint`

**Purpose**: Query the endpoint URL of the Core system

Request body format:

```json
{
  "method": "get_core_endpoint",
  "params": {
    "service_name": "portal"
  },
  "id": "1235"
}
```

The `service_name` parameter is optional. If provided, it returns the endpoint for a specific core service (e.g., "portal", "consultant", "knowledge"). If omitted, returns the main core endpoint.

Response body format:

```json
{
    "id": "the corresponding request id",
    "result": {
        "status": "success or error",
        "content": "the return value of the called method"
    }
}
```

On success, the content would be:

```json
{
  "service_name": "portal",
  "endpoint_url": "https://core.telcenter.vn/api/portal",
  "api_version": "1.0.0",
  "status": "active",
  "last_health_check": "2025-12-08T10:30:00Z"
}
```

On failure (`status == 'error'`), the content would
reflect what is going on. If the failure is
caused by some `Exception`, the content should
be `str(e)` with `e` being the `Exception` instance
that was the culprit.

In special error cases, the content must be:
- `"Service not found"` if the specified service_name does not exist
- `"Core service unavailable"` if the core service is not responding

### A09 Method: `list_active_partners`

**Purpose**: Get a list of all currently active partners with their endpoints

Request body format:

```json
{
  "method": "list_active_partners",
  "params": {},
  "id": "1236"
}
```

Response body format:

```json
{
    "id": "the corresponding request id",
    "result": {
        "status": "success or error",
        "content": "the return value of the called method"
    }
}
```

On success, the content would be:

```json
{
  "partners": [
    {
      "partner_id": "uuid-string-1",
      "partner_name": "Viettel",
      "endpoint_url": "https://partner.viettel.com.vn/api",
      "status": "active"
    },
    {
      "partner_id": "uuid-string-2",
      "partner_name": "Mobifone",
      "endpoint_url": "https://partner.mobifone.com.vn/api",
      "status": "active"
    },
    {
      "partner_id": "uuid-string-3",
      "partner_name": "Vinaphone",
      "endpoint_url": "https://partner.vinaphone.com.vn/api",
      "status": "active"
    }
  ],
  "total_count": 3,
  "timestamp": "2025-12-08T10:30:00Z"
}
```

On failure (`status == 'error'`), the content would
reflect what is going on. If the failure is
caused by some `Exception`, the content should
be `str(e)` with `e` being the `Exception` instance
that was the culprit.

In special error cases, the content must be:
- `"No active partners"` if there are no partners currently in active status
- `"Database connection error"` if unable to query the partner database
