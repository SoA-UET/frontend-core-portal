# A32 Group

This is the group of APIs between
the [Partner's Local Knowledge Service](../services/partner/S11_Partner_Local_Knowledge_Service.md)
and [Partner's File Importing AI Agent](../services/partner/S15_File_Importing_AI_Agent.md).

This API consists of 1 API.

## A32

This API is based on RabbitMQ.

The API has 1 method.

### A32 Method: `process_file_import`

This method is called by S11 to request S15 to process an uploaded file and extract telecom service knowledge.

Request body format:

```json
{
  "method": "process_file_import",
  "params": {
    "file_content_base64": "base64_encoded_file_content_here...",
    "file_reference": {
      "storage": "seaweed",
      "file_id": "<seaweed_fid_or_file_id>",
      "file_url": "https://seaweed.master:9333/<file_id>",
      "file_size": 123456
    }
  },
  "id": "import_req_1234"
}
```

Supported file types:
- `"pdf"` - PDF documents

Notes on file transfer and SeaweedFS:
- Preferred flow: upload the file to SeaweedFS first (via HTTP multipart upload), then send `A32` with `file_reference` pointing to the SeaweedFS `file_id`/`file_url`.
- Alternative flow: include `file_content_base64` directly in the `A32` message (not recommended for large files).
- When S15 receives a `file_content_base64`, it MUST store the file into SeaweedFS and return the `file_reference` in the response so the file is found later.

SeaweedFS configuration (set via `.env`):
- `SEAWEED_MASTER_URL` (e.g. `http://seaweed-master:9333`)
- `SEAWEED_COLLECTION` (optional collection name)

Response format (success):

```json
{
  "id": "import_req_1234",
  "result": {
    "status": "accepted",
    "staging_id": "stg_7890",
    "file_reference": {
      "storage": "seaweed",
      "file_id": "<seaweed_fid_or_file_id>",
      "file_url": "https://seaweed.master:9333/<file_id>",
      "file_size": 123456
    }
  }
}
```

Response body format:

```json
{
    "id": "the corresponding request id",
    "result": {
        "status": "success or error",
        "content": "the return value of the called method"
    }
}
```

On failure (`status == 'error'`), the content would
reflect what is going on. If the failure is
caused by some `Exception`, the content should
be `str(e)` with `e` being the `Exception` instance
that was the culprit.

In special error cases:
- If `file_content` is missing or cannot be decoded, the content must be `"Invalid or missing file content"`
- If `file_type` is unsupported, the content must be `"Unsupported file type: <file_type>"`
- If the file is corrupted or cannot be parsed, the content must be `"File parsing failed: <details>"`
- If no valid data can be extracted, the content must be `"No valid telecom service data found in file"`
- If the file is too large (>50MB), the content must be `"File size exceeds maximum limit of 50MB"`
- If confidence score is below threshold (<0.5), the content must be `"Extraction confidence too low: <score>. Manual review required"`

## Queue Configuration

- Request Queue: `file_import_requests`
- Response Queue: `file_import_responses`

Both queues should be configurable via `.env` file with the following variables:
- `FILE_IMPORT_REQUEST_QUEUE`
- `FILE_IMPORT_RESPONSE_QUEUE`

## Notes

- The `_confidence` field in each dataframe row indicates the AI's confidence in the extraction accuracy for that specific entry (0.0 to 1.0)
- Files should be base64 encoded before transmission
- Processing time depends on file size and complexity
- The AI agent may skip rows with insufficient data quality
- Warnings array provides transparency about extraction issues
