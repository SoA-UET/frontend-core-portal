# A08 Group

This is the group of APIs between
the [Core's Knowledge Validator Service](../services/core/S05_Knowledge_Validator_Service.md)
and [Core's Knowledge Service](../services/core/S03_Knowledge_Service.md).

This API consists of 1 API.

## A08

This API is based on RabbitMQ.

The API has 1 methods.

### A08 Method: `store_validated_knowledge`

This method is called by S05 to store validated knowledge into S03's knowledge database.

Response body format:

```json
{
    "id": "the corresponding request id",
    "result": {
        "status": "success or error",
        "content": "the return value of the called method"
    }
}
```

On success, the content would be:

```json
{
  "stored_count": 2,
  "updated_count": 0,
  "message": "Knowledge stored successfully"
}
```

On failure (`status == 'error'`), the content would
reflect what is going on. If the failure is
caused by some `Exception`, the content should
be `str(e)` with `e` being the `Exception` instance
that was the culprit.

In special error cases:
- If `source` is missing or invalid, the content must be `"Invalid or missing source field"`
- If `df` is empty or malformed, the content must be `"Invalid dataframe format"`
- If duplicate detection fails, the content must be `"Duplicate detection error: <details>"`
- If database storage fails, the content must be `"Storage failed: <details>"`

## Queue Configuration

- Request Queue: `knowledge_validator_to_knowledge_requests`
- Response Queue: `knowledge_validator_to_knowledge_responses`

Both queues should be configurable via `.env` file with the following variables:
- `KNOWLEDGE_VALIDATOR_TO_KNOWLEDGE_REQUEST_QUEUE`
- `KNOWLEDGE_VALIDATOR_TO_KNOWLEDGE_RESPONSE_QUEUE`
