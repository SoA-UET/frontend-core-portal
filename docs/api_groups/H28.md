# H28 Group

This is the group of APIs between the **Partner Portal** and **S11 Partner Local Knowledge Service**

This API consists of **1** API(s).

## H28

**Direction:** Partner Portal(Frontend) → S11

This API is based on **HTTP**

The API has **3** methods.

### H28 Method: `crud_packages`

This method handles CRUD operations for Packages (TP07, TP08, TP09, TP10).

Request body format:

```json
{
    "method": "crud_packages",
    "params": {
        "action": "create",
        "data": {
            "Mã dịch vụ": "SD70",
            "Thời gian thanh toán": "Trả trước",
            "Giá (VNĐ)": 70000,
            "Chu kỳ (ngày)": 30,
            "4G tốc độ tiêu chuẩn/ngày": 1,
            "4G tốc độ cao/ngày": 0,
            "Chi tiết": "Gói cước data 4G",
            "Tự động gia hạn": "Có",
            "Cú pháp đăng ký": "SD70 DK8 gửi 290"
        }
    },
    "id": "h28-pkg-001"
}
```

*Note: `action` can be `list`, `create`, `update`, `delete`.*
- For `list`: `data` contains filters like `{ "page": 1, "limit": 10 }`.
- For `create`: `data` contains package fields.
- For `update`: `data` contains `{ "id": "pkg-101", ...fields_to_update }`.
- For `delete`: `data` contains `{ "id": "pkg-101" }`.

Response body format:

```json
{
    "id": "h28-pkg-001",
    "result": {
        "status": "success",
        "content": {
            "id": "pkg-101",
            "message": "Package created successfully"
        }
    }
}
```

On success, the content would be **the result of the CRUD operation (created/updated/deleted item or list of items)**.

On failure (`status == 'error'`), the content would
reflect what is going on. If the failure is
caused by some `Exception`, the content should
be `str(e)` with `e` being the `Exception` instance
that was the culprit.

In special error cases:
- If `action` is invalid, the content must be `"Invalid action. Must be one of: list, create, update, delete"`
- If `id` is missing for update/delete, the content must be `"Missing required field: id"`
- If duplicate package code, the content must be `"Duplicate package code: <code>"`

### H28 Method: `import_file`

This method handles file import for bulk knowledge data. The file is stored in SeaweedFS and then processed by S15 File Importing AI Agent.

Request body format (multipart/form-data):

```
POST /api/v1/local-knowledge/import-file
Content-Type: multipart/form-data

file: <binary_file_data>
metadata: {
    "source": "Viettel",
    "description": "Dữ liệu gói cước Q4 2025",
    "import_type": "local_only"
}
```

Response body format:

```json
{
    "id": "h28-import-001",
    "result": {
        "status": "success",
        "content": {
            "import_id": "import-12345",
            "seaweed_file_id": "3,01637037d6",
        }
    }
}
```

On success, the content would be **the import task ID and SeaweedFS file ID for tracking**.

On failure (`status == 'error'`), the content would
reflect what is going on. If the failure is
caused by some `Exception`, the content should
be `str(e)` with `e` being the `Exception` instance
that was the culprit.

In special error cases:
- If file format is not supported, the content must be `"Unsupported file format. Supported: .pdf, .xlsx, .xls, .docx"`
- If file size exceeds limit, the content must be `"File size exceeds maximum limit of 50MB"`
- If SeaweedFS upload fails, the content must be `"Failed to upload file to storage: <details>"`

## Configuration

Base URL should be configurable via `.env`:
- `PARTNER_LOCAL_KNOWLEDGE_SERVICE_URL` (e.g., `http://localhost:7011`)

SeaweedFS configuration:
- `SEAWEED_MASTER_URL` (e.g., `http://seaweed-master:9333`)
- `SEAWEED_PUBLIC_URL` (optional, for public file access)

## Notes

- All requests require JWT authentication with partner employee credentials
- Rate limiting: 60 requests per minute per user
- Supported file types for import: .pdf, .xlsx, .xls, .docx
- Maximum file size: 50MB
- File processing is asynchronous via S15 File Importing AI Agent (A32)
- Local knowledge is immediately available for consultation after CRUD operations
